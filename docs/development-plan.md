# 공간 개발 계획 초안

## 1. 검증할 질문

설명·계정·과제 없이 정원과 꾸띠에 들어가 잠깐 쉴 수 있을까요? 먼저 이 한 가지를 검증합니다. 교육 콘텐츠·성장 시스템·멀티플레이보다 작고 완결된 휴식 경험을 우선합니다.

## 2. 단계와 완료 기준

| 단계 | 산출물 | 통과 기준 |
| --- | --- | --- |
| A. 시각 콘티 | iPhone 3장: 정원 입구·꾸띠 문·차와 휴식 | 사용자 구도 승인; 진입·머무름·종료가 보이고 강제 행동이 없음 |
| B. 정적 시제품 | 세 장면과 최소 이동, 선택적 소리, 저사양 대체 화면 | 계정·채팅·기분 공개·타이머 없음; 차를 누르지 않아도 이용 가능 |
| C. 소규모 관찰 | 동의받은 5명의 짧은 사용 관찰과 개선 목록 | 아래 제안 기준 검토 후 유지·수정·중단 결정 |
| D. 제한 확장 | 별도 법당과 NPC 한 명 | 가상 인물 표시, 개인 공간과 분리, 기존 휴식 흐름 유지 |

현재 완료된 것은 기획 문서와 폴더 준비뿐입니다. 시각 콘티 제작과 실제 구현은 다음 작업입니다.

## 3. 제안된 관찰 기준

- 5명 중 4명이 60초 안에 도움 없이 휴식 공간에 들어갑니다.
- 5명 중 3명이 편안함을 느낀 구체적인 순간을 하나 설명합니다.
- 이 수치는 초기 방향 판단을 위한 제안이지 통계적 효능이나 치료 효과의 증명이 아닙니다.
- 약 3분은 관찰 세션의 가정입니다. 서비스 화면에 제한 시간이나 성취 목표를 넣지 않습니다.
- 참여자의 동의를 받고 최소한의 익명 관찰만 남깁니다. 개인적인 감정·건강 정보나 원문 대화를 공개 저장소에 남기지 않습니다.
- 기준에 못 미치면 콘텐츠를 늘리기보다 첫 진입과 머무는 장면을 먼저 고칩니다.

## 4. 기기·접근성·품질

iPhone Safari를 먼저 확인하고 Android 및 데스크톱에서 같은 핵심 흐름을 확인합니다. 정확한 지원 버전과 성능 예산은 기기 시험 뒤 정합니다.

- 터치 영역, 텍스트 대비, 키보드 이동, 포커스 표시, 버튼의 접근 가능한 이름을 확인합니다.
- 소리는 기본으로 강제 재생하지 않고 이용자가 선택하게 합니다. 소리가 없어도 이용할 수 있어야 합니다.
- 움직임 줄이기 설정과 정적인 대체 경험을 고려합니다.
- WebGL 미지원·실패 또는 낮은 성능에서는 2D 대체 흐름을 제공합니다.
- 화면 회전·재진입·뒤로 가기와 중간 종료를 확인합니다.
- 이미지·음원·글꼴·모델의 출처와 사용 권한을 확인하고 개인정보·비밀키를 포함하지 않습니다.

## 5. 기술 후보와 보류 사항

Astro + TypeScript, 필요한 장면에 Three.js/WebGL2, GLB 자산과 2D 대체 화면을 후보로 검토합니다. 최종 스택은 아니며, 시각 콘티를 구현하는 데 3D가 실제로 필요한지부터 판단합니다. 현재 패키지 설치나 네트워크 서비스 연결은 없습니다.

초기 시험은 정적 사이트와 NPC를 전제로 합니다. 로그인·실시간 서버·실제 이용자 동시 입장·푸시 알림·결제·개인 상태 수집은 범위 밖입니다. Pages 배포와 도메인 설정도 별도 승인 전 진행하지 않습니다.

## 6. 일정 가정과 의사결정

3주, 총 40–60시간은 작업량을 가늠하는 가정입니다. 확정 일정·비용 견적·제공 약속이 아닙니다. 자산 제작, 수정 횟수, 접근성·기기 시험 범위에 따라 다시 산정합니다.

A 승인 → B 구현 → C 관찰 → D 여부 결정 순서로 진행합니다. 교학·미술·공개·비용 결정은 사용자에게 남깁니다. 후보 콘티나 기능의 자동 검증 통과를 최종 사용자 승인으로 바꾸지 않습니다.
